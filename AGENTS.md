# Agent guide

## Working order

1. Read `spec/design_input` and update the relevant design note before behavior changes.
2. Keep cross-cutting values in `src/obs_html/cfg.json` with matching schema constraints.
3. Implement the smallest behavior consistent with the approved design.
4. Add a regression test first, run the affected tests, and exercise the affected CLI path.
5. Follow the knowledge-ownership and change-locality rules in
   [`quality.md`](spec/design_input/quality.md).

## Public safety

This repository must remain publishable. The shared
[Public safety](../se/AGENTS.md#public-safety) policy from `se` applies. Install its local Git
hooks with `setup.ps1 -Repo <repository>` and run its `public_check.py` before sharing changes.
Do not copy the shared process guidance into this repository.

## Invariants

- `uv.lock` is generated by uv, committed, and treated like a dotfile.
- Never edit `uv.lock` manually; let uv update it.
- Generated content belongs in `data/data_output` or `spec/design_output` and is ignored.
- One owner owns each fact; other locations link to it.
- Follow se's [authored-prose preservation rule](../se/.github/skills/work-model/SKILL.md#rules-for-all-roles).
- Do not add compatibility aliases, shims, or fallbacks unless explicitly requested.
