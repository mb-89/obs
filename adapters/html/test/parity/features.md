# Features of the HTML adapter

Reader: whoever changes this adapter or the core in front of it, and the dispatcher reading what
the adapter offers and how it differs from the interim adapter obs#3 deleted.

One row per feature: every CLI option and settings key of this adapter (the gate compares these
sections against its own parser and settings schema), every capability, reader control, input or
check, and output form. The rows the interim adapter's features gave stay as the record; its
column says what the interim did, and nothing runs it. A feature the interim did not have says
"added". The gate, [test_parity_table.py](test_parity_table.py), owns the rules each row's status
and evidence follow.

"Integrated" means this adapter (`obs-html`) and the core in front of it
(`obs-document --adapter html`). Where the interim's values were the reference (the settings'
defaults and limits), the reference is now this adapter's `cfg.schema.json` and the core's
`config.schema.json` as they stand. A "missing" row names the issue that tracks the gap.

Paths in the Evidence column are from the repository root. `parity-browser` below stands for
`adapters/html/test/test_parity_browser.py`, `dom` for the DOM contract script those tests run;
the gate reads only the code spans.
